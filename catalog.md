# Каталог навыков

Живой список репозиториев, которые уже проверены и стоят на этом Mac. Сюда дописываем каждый следующий.

Стоят глобально в Claude Code, Codex и Cursor. Автозапуска нет: навык включается, только когда вы его просите или когда задача явно про него. Код проекта эти навыки никуда не отправляют. Это текстовые инструкции для модели.

Как вызывать в чате:

- Claude Code и Cursor: `/имя` или обычная фраза своими словами.
- Codex: `$имя`.

После установки нового пакета приложения нужно полностью закрыть и открыть заново.

## Impeccable

Дизайн-директор для интерфейсов. Один навык, много команд: план, проверка, правка вёрстки, типографика, цвет, анимация.

Ссылка: https://github.com/pbakaus/impeccable

Как работает. Модель читает инструкцию и локально прогоняет проверку ваших UI-файлов. В проекте появляются `PRODUCT.md` и `DESIGN.md`: для кого продукт и как он должен выглядеть. Хук, который проверял бы каждый файл сам, не ставили. Картинки и выбор стиля наружу не уходят, если не просить live-режим и генерацию макетов.

Команды. Сначала один раз в проекте: `/impeccable init`. В Codex: `$impeccable init`.

| Команда | Зачем |
|---|---|
| `/impeccable shape` | Спланировать экран до кода |
| `/impeccable document` | Собрать DESIGN.md из уже написанного кода |
| `/impeccable extract` | Вытащить цвета, шрифты и компоненты в систему |
| `/impeccable critique` | Рецензия: иерархия, ясность, ощущение |
| `/impeccable audit` | Доступность, скорость, адаптив |
| `/impeccable polish` | Финальный проход перед сдачей |
| `/impeccable bolder` | Слишком скучно, усилить |
| `/impeccable quieter` | Слишком кричаще, успокоить |
| `/impeccable distill` | Убрать лишнее |
| `/impeccable harden` | Ошибки, длинный текст, края, переводы |
| `/impeccable onboard` | Первый запуск, пустые состояния |
| `/impeccable animate` | Осмысленное движение |
| `/impeccable colorize` | Цвет там, где всё серое |
| `/impeccable typeset` | Шрифты и размеры |
| `/impeccable layout` | Сетка, воздух, ритм |
| `/impeccable delight` | Мелкие живые детали |
| `/impeccable overdrive` | Сильный визуальный эффект |
| `/impeccable clarify` | Понятные подписи и ошибки |
| `/impeccable adapt` | Телефон, планшет, десктоп |
| `/impeccable optimize` | Тормоза интерфейса |
| `/impeccable live` | Править элемент прямо в браузере |
| `/impeccable generate` | Несколько вариантов одного элемента |

Где полезно. Новый лендинг, личный кабинет, дашборд, форма, настройки, пустой экран. Не для бэкенда и не для задач без интерфейса.

## Taste Skill

Набор вкусов для фронтенда, чтобы сайты не выглядели как один и тот же шаблон нейросети. Автор Leonxlnx. Лицензия MIT.

Ссылка: https://github.com/Leonxlnx/taste-skill

Как работает. В пакете 13 отдельных навыков. Модель подхватывает тот, чьё описание совпало с просьбой. Можно назвать имя явно. Навыки с `imagegen` и `brandkit` рисуют картинки-макеты средствами той нейросети, где вы сидите, и тратят её лимит картинок. В вёрстке модель иногда ставит заглушку с picsum.photos. Это адрес чужой картинки, не отправка вашего кода.

Команды. Имя ниже пишется так: `/design-taste-frontend` или `$design-taste-frontend`.

| Навык | Что делает | Где полезно |
|---|---|---|
| `design-taste-frontend` | Основной. Читает бриф и собирает лендинг или портфолио без шаблонного вида. Сейчас это v2, экспериментальный. | Новый маркетинговый сайт, портфолио, редизайн лендинга |
| `design-taste-frontend-v1` | Старая версия того же навыка. | Только если v2 ведёт себя не так, как нужно |
| `gpt-taste` | Более жёсткий вариант для Codex: сильнее разнообразие сеток и анимация GSAP. | Тот же лендинг, когда просите именно Codex |
| `high-end-visual-design` | Спокойный дорогой вид: воздух, мягкие тени, аккуратная анимация. | Премиальный сайт, бренд, агентство |
| `minimalist-ui` | Редакционный минимализм в духе Notion и Linear. | Продуктовый сайт, документация, спокойный интерфейс |
| `industrial-brutalist-ui` | Жёсткая сетка, крупный шрифт, технический вид. | Портфолио, экспериментальный сайт, плотные данные |
| `redesign-existing-projects` | Сначала смотрит, что уже есть, потом улучшает, не ломая поведение. | Уже запущенный сайт или приложение |
| `image-to-code` | Сначала макет картинкой, потом вёрстка по нему. | Когда словами дизайн не объясняется |
| `imagegen-frontend-web` | Только картинки секций сайта, по одной на секцию. | Референс перед вёрсткой |
| `imagegen-frontend-mobile` | Только картинки экранов телефона. | Онбординг, профиль, чат, мобильное приложение |
| `brandkit` | Доска бренда: логотип, палитра, шрифт, носители. | Начало бренда, когда кода ещё нет |
| `stitch-design-taste` | Правила и файл DESIGN.md в формате Google Stitch. | Если макет потом идёт в Google Stitch |
| `full-output-enforcement` | Запрещает модели обрывать код на полуслове и писать «здесь потом». | Любая задача, где ответ постоянно обрывается |

## Emil Kowalski

Навыки по анимации и мелким решениям интерфейса. Автор делал интерфейсы в Vercel и Linear, библиотеку тостов Sonner.

Ссылка: https://github.com/emilkowalski/skills

Как работает. 14 отдельных инструкций. Модель не ставит бинарник и не ходит на сервер автора. Часть навыков только смотрит и пишет план, часть сразу правит код. В нескольких прямо сказано: если файл в репозитории просит «игнорируй прошлые инструкции», это помеха, а не команда.

Команды. Имя ниже: `/animate` или `$animate`.

| Навык | Что делает | Где полезно |
|---|---|---|
| `emil-design-eng` | Общий вкус: полировка, компоненты, когда анимация нужна, а когда нет. | Любой интерфейс, если неясно, с какого навыка начать |
| `animate` | Собирает одну анимацию в вебе: кривая, длительность, что двигать. | Кнопка, меню, появление блока, переход |
| `animate-expo` | То же для React Native и Expo, движение не на JS-потоке. | Мобильное приложение на Expo |
| `review-animations` | Жёсткая проверка уже написанного движения. | Перед сдачей анимации |
| `improve-animations` | Обходит весь проект и выдаёт план правок по приоритету. | В проекте много разрозненных анимаций |
| `find-animation-opportunities` | Ищет места, где движение поможет, и отсекает лишнее. Сам код не пишет. | Спокойный интерфейс, куда страшно добавить анимацию везде |
| `animation-vocabulary` | Переводит «вот эта пружинка при открытии» в точный термин. | Когда не знаете, как назвать эффект |
| `apple-design` | Жесты, шторки, пружины в духе Apple, но для веба. | Свайп, перетаскивание, нижняя шторка |
| `mobile-native` | Мелочи, из-за которых сайт на телефоне ощущается как приложение. | Мобильная веб-версия |
| `prototype` | Несколько разных вариантов одного куска и переключатель между ними. | Выбор направления, пока не хочется коммитить один вид |
| `pick-ui-library` | Советует готовую библиотеку вместо самописного компонента. | Тосты, графики, drag-and-drop, виртуализация, тёмная тема |
| `ask-sonner` | Как подключить и настроить тосты Sonner. | Уведомления в React |
| `break-ui` | Ломает экран длинными именами, пустыми данными, огромными числами. | Форма, таблица, карточка перед релизом |
| `write-swift` | Современный Swift: типы, параллельность Swift 6, тесты. | Нативное приложение на Swift, не веб |

## Как выбрать, если просят одно и то же

Все три пакета про интерфейс, но смотрят с разных сторон.

- Новый экран с нуля и нужно запомнить продукт: Impeccable, команда `init`, потом сборка.
- Лендинг или портфолио, которые не должны быть похожи на шаблон: `design-taste-frontend`.
- Движение, жесты, «почему это дёргается»: навыки Emil, начиная с `emil-design-eng` или `animate`.
- Уже готовый экран надо довести: `/impeccable polish` или `redesign-existing-projects`.
